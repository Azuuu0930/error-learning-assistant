# 学生・先生の使い方と匿名相談カードの設計

日付：2026-10-28（日本時間）。基準コミット：e4e6f93。
状態：設計確認待ち。アプリ本体は未変更。

## 目的と対象

学生がPython・C・C++のエラーで止まったとき、ヒントで考え、必要なら先生へ困りごとの種類を伝えられるようにする。
先生は受け取ったカードを集めて、復習や声かけの参考になる傾向を確認する。
診断結果の件数を理解不足や学習効果の測定と扱わず、対応環境が不明な点も残す。

## 比較した方式と選択

1. **匿名相談カードの任意ダウンロードと一括読込（選択済み）。** アカウント・共有DBが不要。学生から先生へのファイル受け渡しが必要で、リアルタイム集計はできない。ユーザーが2026-10-28にこの方式を選択した。
2. **先生用の教材・エラー例準備を先に作る。** 記録収集は不要だが、困りごとの傾向を把握する目的を直接は満たさない。今回は採用しない。

ライブ授業ルーム・認証・中央保存は、教員と収集許可が未確定な現段階では作業量と運用範囲が増えるため採用しない。

## 学生の画面

- 最上部で「学生」「先生」を切り替える。初期表示は学生。これは操作の切替であり本人確認ではない。
- 既存の解析・検索・ヒント・表示モード・任意AIの条件を維持する。既存の入力キーや解析APIを大規模に変更しない。
- Python・C・C++で入力例、修正例、コードの色付け、ヒントの語句を合わせる。
- サイドバーのサンプルは選択中の言語に合わせ、C/C++の選択中にPythonへ勝手に戻る混乱を防ぐ。Pythonサンプルと既存テストは維持する。
- 解析後「先生に相談する」を開ける。コードを直す答えやASTの詳細をカード機能から先に見せない。
- 学生が「まだ困っている／次に試すことが分かった／解決した（自己申告）」を選び、実行環境を分かる範囲で既定の選択肢から選べる。初期値は未回答・不明。
- 保存内容を日本語の項目名でプレビューし、任意の操作でJSONカードをダウンロードする。自動提出・自動収集はしない。
- コードやログ本文がカードに入らないため、このカードだけでは先生がコードの問題を直接直せないことも伝える。コードの別共有は授業のルールに従う。

## カードの内容と境界

バージョン付きの厳密なJSON。すべて既定値・列挙値・制限付き識別子で、自由入力を設けない。

- schema_version：1。
- card_id：解析結果ごとにランダムUUID。入力変更・再解析で新規、同じ結果の再ダウンロードや状態変更では同じID。
- app_release：このカード機能の固定リリース識別子。Gitコミットを実行時に推測しない。
- language：python / c / cpp。
- environment：unknown / python / notebook / gcc / clang / msvc / other。本人の選択で、IDE名からコンパイラを推定しない。
- error_type：既知の例外名・CompilationError・LinkerError・SegmentationFault・unknownのみ。独自例外名をそのまま送らない。
- diagnostic_code：MSVCのC/LNK等の制限された診断コード、またはnull。GCC等に固定コードがない場合はnull。Pythonではnull。
- category：既知のアプリ分類、またはunknown。
- phase：compile / link / runtime / unknown。Pythonの構文エラーはcompileとして表示時に「構文確認」と補足する。ログから推定した段階であり再実行した事実ではない。
- concept_candidates：アプリ分類から保守的に求めた固定語彙の学習概念候補。複数または空を許す。名前未宣言をスコープ理解不足と断定しない。
- analysis_status：complete / partial / unrecognized。completeは原因確定や解決を意味しない。
- hint_step：画面で確認した0〜3。
- fix_viewed：ヒントモードで実際に開いたかのboolean。通常モードでは開閉を測れないためnullとして未計測を表示する。
- learning_status：unanswered / stuck / next_step / resolved。解決は自己申告と明記する。

含めないもの：氏名、学籍番号、学校・授業・個人の識別子、ファイル名・パス、コード、ログ本文、変数名、リテラル、自由記述、送信時刻、APIキー。
カードIDは人物識別ではない。同じ学生の別相談は別件になり、人数や個人の履歴は集計できない。
ダウンロード後のファイルは本人が保管・受け渡しを管理する。「完全に個人を特定できない」ことまでは保証しない。
任意AIへのカード送信は追加しない。

## 先生の画面

- 学生用のコード入力から独立した先生の入口を用意し、「カードを受け取る→読み込む→傾向を確認する」の短い手順を示す。
- JSONカードを複数アップロード。画面・案内・グラフの見出しは日本語にする。新しい外部サービス・依存パッケージは追加しない。
- カードはアプリサーバーへ届くことを説明。授業の許可に従って利用し、独自の永続保存・全体共有・外部AI送信は行わない。ホスティング側の取扱いは別である。
- 1ファイル16KiB、最大100ファイル、合計1MiB。これを超えたバッチは処理前に拒否し、ZIP・実行・pickleを扱わない。
- UTF-8のJSONのみ。余分なキー、不明な版、不正な型（boolをint扱いしない）、列挙外の値、不正ID、矛盾した言語・例外名・段階・診断コード・概念を拒否する。
- 不正ファイルは他の正常カードを巻き込まず理由を案内する。ログ本文や入力本文をエラー表示へ反映しない。
- 同じID・同じ内容は1件にまとめ、重複件数を知らせる。同じIDで内容が異なる場合、そのIDのカードはすべて集計から外して矛盾として知らせる。ファイル順で結果を変えない。
- 件数、まだ困っている件数、ヒント3まで見た件数、未回答件数を表示する。人物の数ではなく相談カードの件数。
- 言語と発生段階で絞り込み、言語固有の例外名・診断コードと、学習概念候補を別々に表・グラフで示す。未分類も残す。
- 概念は「復習候補」であって理解不足の確定ではない。複数候補を持つ場合は候補件数と相談件数が一致しないことを明記。
- 本人回答の状態別表と、通常モードで修正例の閲覧が未計測である件数も確認できる。
- 集計だけをCSVダウンロードできる。安全な固定ラベルと数値のみを出し、コードやカードの自由値は出さない。
- 読み込んだカードを画面から消去できる。通常の再描画で件数を加算しない。
- 実データ未入力時は件数を捏造せず、説明だけを表示する。模擬データが必要なら明確に「デモ」と表示し、実カードに混ぜない。今回はデモデータ自動投入をしない。

## C/C++の既知の誤案内を修正

- 未認識ログ・警告のみ・正常ビルド文からコンパイル失敗や原因を断定しない。種類が不明なら説明・修正例もその状態に合わせる。未知＝正常とは扱わない。
- CモードへC++の修正例や入力例を出さない。C/C++に対応する色付けを選ぶ。
- コンパイル・リンク・実行に合わせたヒントと読み取り方へ切り替える。
- MSVC診断コードをParsedError末尾の任意項目として保持し、既存の位置引数を壊さない。既知コードから補助分類できるが、英語本文があるケースの挙動を維持する。
- 日本語のエラー/警告等の表記に限定的に対応し、未知コードを無理に細分化しない。対象授業の実ログはまだないため、実環境で検証済みとは書かない。
- C/C++のAST・型推論・完全な実行時例外対応は今回追加しない。Pythonの診断方式や評価指標と同じ精度だとは主張しない。

## 構成

- src/classroom.py：カード生成・厳密検証・重複/矛盾処理・集計・CSV。StreamlitやAPIに依存しない。
- src/classroom_ui.py：学生の任意カード保存と先生の読込・集計画面。既存app.pyから呼ぶ。
- 言語別サンプルは小さい別モジュールか既存のサンプル読込に追加。既存Python用JSONは維持。
- app.py：役割切替と呼出し、言語に合わせた表示。既存解析機能は引き続きsrcに置く。
- models.py / c_family.py / explanations.py / hints.py：上記の限定されたC/C++修正。
- 既存の濃紺・青緑、レスポンシブ、動きを減らす設定を引き継ぐ。装飾によってヒントやファイルの検証状態を隠さない。
- 既存の調査資料・検証履歴は保ち、今回の実装・テストと区別して追記する。現在の作業ツリーの資料変更を失わない。

## 受け入れ条件

1. 初期表示は従来の学生機能。先生へ切り替えても学生の秘密の入力を表示・集計しない。
2. Python/C/C++で、解析→段階式ヒント→任意カード保存→先生の一括読込→言語別集計の一連が動く。
3. 秘密の文字列を入力ログ・パス・変数名へ仕込んでもカード/CSVには含まれない。
4. 不正JSON、余分なキー、巨大ファイル、重複・矛盾、再描画、カード消去を検証する。
5. Cの修正例にC++構文が混ざらず、未知ログ・正常文を失敗と断定しない。
6. 既存589件のテストと評価器を維持し、機能・無警告・画面の回帰テストを追加する。件数・実際の結果を報告する。
7. 公開版へ反映後に学生/先生両画面の短い動作確認を行う。Streamlitのモジュール更新が混在した場合は運営側で再起動して確認し、利用者へ再起動操作を要求しない。
8. READMEの集計未実装という説明を実装範囲に合わせ、学生への効果・教師の活用実績は未検証のままとする。
