## C/C++の段階別の対応と制限

| 段階 | 現在拾えるもの | 未対応・不十分なもの |
|---|---|---|
| コンパイル | error / fatal error行、名前未宣言・一部の型不一致・ヘッダー不足・文法等の定型文 | 日本語本文の概念分類、日本語の重大度表記、IDE独自形式。一般のエラー行は大分類のみ |
| リンク | undefined reference / undefined symbol / unresolved external symbol等 | 全リンカー形式の保証、ビルド設定の検証、定義元の特定 |
| 実行 | Segmentation fault / access violationと一般的な確認点 | C++標準例外、AddressSanitizer等の専用診断、スタック解析、発生行・原因の確定 |

## 授業での操作テスト前の修正候補

1. **未認識のC/C++ログでもコンパイル失敗を断定する。** Build succeeded、警告だけ、未対応の実行時例外にも「コンパイラがコードを受け付けず、実行ファイルを作れませんでした」と表示した。未知形式から失敗を断定しない修正が必要。
2. **Cモードの入力例・一部の修正例がC++。** 名前未宣言でiostream / std::coutの例を返す。修正例の色付けもC/C++ともPython指定。言語別の例と表示にする必要がある。
3. **C/C++のヒントに「最後の例外行」というPython向けの表現がある。** コンパイル・リンク・実行に合わせた案内が必要。
4. **日本語の診断文では分類が弱い。** 作成したerror C2065＋日本語本文は大分類compile止まり、エラー C2065は未認識。実際の対象環境の出力を入手して対応範囲を決める。
5. **サイドバーのサンプルはPython用。** 選ぶと対象言語もPythonへ変わる。C/C++授業での誤操作を防ぐ区別が必要。

上記は発見事項で、この調査ではアプリ本体を変更していない。協力先探し・聞き取りは進め、C/C++の操作テスト用の版は修正・実ログ検証後に指定する。
