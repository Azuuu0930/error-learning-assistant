# 現地でお願いする調査と利用協力

更新：2026-10-28。**協力先・授業環境は未確認、聞き取り・学生テストは未実施**です。
現地での相談・募集・日程調整はあなたにお願いします。こちらから先生・学生・運営に連絡していません。結果や利用者の声を作って埋めないでください。

Python限定の募集方針を撤回し、**Python・C・C++の対象授業での安定性を優先**します。[言語別対応表](LANGUAGE_READINESS.md)に、実装・制限・検証結果と要修正点をまとめました。

## 最初にお願いする3点

1. **大学1〜2年生の基礎授業と、相談できる先生1人を探す。** 使用言語、コンパイラ名・版、IDE/実行場所、OS、診断の表示言語、現在の学習内容を確認する。学生数人・授業外の短い試用から相談できればよい。人数は調査規模の目安で、効果を一般化できる規模という意味ではない。
2. **協力可能な範囲を先生に聞く。** 授業内/外、募集案内、ヒント・修正例の方針、アプリサーバーへのコード送信、任意の外部AI送信、記録してよい情報と禁止情報、必要手続きを確認。参加・不参加を成績と結び付けない。
3. **共有許可のある診断出力を受け取る。** 氏名・学籍番号・個人パス・秘密情報を除く。実行に使った操作やコマンド、コンパイラ/IDEの情報も添える。無理にソフトを入れ直したり英語表示に変えてもらったりしない。

まず次だけCodexへ返せれば、環境に合わせて進められます。

```text

対象学年・授業：
使用言語：
コンパイラ名・版：不明
IDE・実行場所・OS：不明
診断の表示言語：不明
現在学んでいる内容：
授業外の短い試用：可／不可／未相談
共有許可のあるログ：あり／なし／未確認
ヒント・修正例の授業方針：未確認
記録・保存・外部送信の許可範囲：未確認
```

## 先生への聞き込み

先にアプリを説明せず、最近の具体例から聞く。

- 最近、学生から受けたエラー相談を一つ、どんな場面だったか教えてください。
- 学生が質問できずに止まっていることに、どう気づきましたか？ 気づけなかった例はありますか？
- 同じ説明を繰り返した場面はありますか？ どの内容でしたか？
- つまずきについて、今どんな記録や手がかりを持っていますか？
- 次の授業や復習を変えるために、何が分かると判断できますか？
- AIのヒントで、してほしいこと・してほしくないことは何ですか？ 修正例を示す条件はありますか？
- 導入の手続きや、先生・学生の負担になる作業は何ですか？ 大会後も短い試用を相談できますか？

その後に現在の機能と制限を説明する。現在は[匿名相談カードの持ち込み集計](CLASSROOM_GUIDE.md)が利用できる。収集の許可が得られる前は項目表だけを提示し、「この情報があったら、最近の授業のどの判断を変えますか」「不要な情報はありますか」と聞く。項目表・模擬カードへの感想と、実際の学生のカード集計を使った判断を区別する。

## 学生への聞き込み

- 最近、どんなエラーで手が止まりましたか？ そのときのどこが分かりませんでしたか？
- 最初に何をしましたか？ 検索・友人・先生・AIなどをどう使いましたか？
- 先生に質問しにくかった具体的な場面はありますか？
- AIの回答を見ても分からなかった経験はありますか？
- 答えが欲しいときと、考え方を理解したいときでは、何を求めますか？
- このアプリを使わないとしたら理由は何ですか？ 今の方法で十分な点はありますか？

「便利ですか」だけで終えず、実体験と操作を聞く。否定的な意見・参加辞退・途中終了も除外しない。

## 試用前に説明・確認すること

「これはアプリの試用で、あなたの能力や成績を採点するものではありません。参加は自由で、途中でやめられ、参加しなくても不利益はありません。匿名の操作メモを開発と発表の集計に使います。コードとログは解析のため公開アプリのサーバーに届き、コードは実行しません。入力欄に履歴保存の案内がある場合、送信したエラー文は成否を問わず、伏せ字処理して改善用の非公開DB（Supabase）に保存されます。完全な匿名化は保証できないため、個人情報や秘密は入れないでください。コード欄は保存せず、当面の閲覧は開発運営者のみで、先生や他の学生へ公開しません。保存期間は運営者が管理します。録音・画面録画は標準手順に含めず、発言や画面の掲載は別に許可を確認します。」

先生と収集項目・閲覧者・メモの削除日・参加IDで撤回できる期限を決め、本人へ伝える。守れる日付が決まるまで記録しない。課題の共有制限と匿名化を確認する。アプリサーバーへの送信と外部AIへの送信は別に説明する。

AIなしでも試用できる。C/C++には追加ガイド・任意AIの画面はない。Pythonで任意AIを使う場合だけ、先生の許可、設定済みの版、限定情報の送信先・内容、本人の送信直前の同意を確認する。実APIの効果は未検証。

## 約20分の利用テスト

利用URL：https://error-learning-assistant.streamlit.app/ 。版は毎回Codexへ確認し、コミットを記録する。
C/C++の既知の誤案内を修正した最新版でも、授業環境の実ログを先に確認する。形式テストの成功だけで本番利用に問題がないとは扱わない。

1. **0〜2分：説明と同意。** 学習段階・環境を確認し、参加IDを渡す。
2. **2〜5分：実体験。** 最近止まった状況と普段の対処方法を聞く。
3. **5〜11分：自由な操作。** 可能なら本人の共有可能なコード・ログ。難しければ授業環境で確認した提供課題。最初からクリック位置や答えを教えない。
4. **11〜15分：次の行動と別問題。** ヒント段階・修正例・迷った箇所・先へ進めたかを記録。可能なら同じ考え方を使う短い別問題で回答と理由を聞く。
5. **15〜20分：感想と援助。** 分かりにくい説明・誤案内・使わない理由を聞く。援助の内容とタイミングを記録する。

解決は「本人の申告」「修正後の実行を観察」を分ける。援助ありの解決をアプリ単独の成果に数えない。時間を測る場合は開始・終了の定義と援助を併記。異なる課題の小標本から時間短縮や因果的な効果を主張しない。

先生に実際の学生カードの集計を見せるのは、収集許可が揃ってから。項目表や動作確認用の模擬カードのレビューを、実データから判断できた成果に置き換えない。

## 匿名で返す記録

[記録テンプレート](FIELD_RECORD_TEMPLATE.md)を1人・1課題に1部コピーする。先生は対象を先生とし、該当しない項目は「対象外」にする。

- 発言（許可された原文）、観察した事実、観察者の解釈を別欄にする。
- 結果は解決／未解決／途中終了。ヒント未閲覧と未観察を区別する。
- 言語固有の診断名・発生段階・学習概念候補を分離。判断できない概念は不明。
- コード・ログ本文は通常の記録欄へ保存しない。開発用に共有する場合だけ、本人・先生の許可範囲を確認し、匿名化した別添にする。
- 発表で使える範囲（集計／匿名要約／発言原文／匿名化画面／不可）を個別に残す。

旧research_records.csvはPython用の旧様式として残す。新しい言語横断の調査には上のテンプレートを使う。現時点では参加者の実績はない。

## 提出材料として整理するもの

実際のつまずき、進めた例と進めなかった例、援助の有無、先生が欲しい情報と利用場面、継続試用の意向を集める。人数・観測数・中断数を明記し、「みんな困っている」「学習効果が証明された」とまとめない。まずは授業環境と協力先だけ返せばよい。
