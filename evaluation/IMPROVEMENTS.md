# 診断性能改善：実装範囲と失敗分析

## 実装した改善

既存のログparser・モデル・Streamlit画面を維持し、AST解析の末尾に `src/literal_analysis.py` を接続しました。新しい外部依存はありません。アプリは入力コードを実行・eval・importしません。

- **リテラルの型・値**：int、float、str、bytes、list、tuple、dict、set、None、boolを限定的に伝播。型の合わない加算・大小比較、Noneや正確な組み込み型の属性不足、不正な添字、明白な範囲外、辞書の欠損キー・ハッシュ不可能なキー、0での除算・剰余、明白なint変換失敗を補助診断します。
- **関数の引数**：同じコード内の直接の関数定義から `inspect.Signature` を作り、不足・位置引数過多・未知keyword・重複を照合します。default値を実行せず、省略可能性だけを使います。位置専用、keyword-only、`*args`、`**kwargs`を考慮し、呼び出し側の展開や定義変更が不明なら診断を控えます。
- **簡単な経路**：定義済み／定義される可能性のある名前を分け、ifの合流や空ループ後の参照を「全ての経路で定義されるとは限らない」と中信頼度で示します。実行されないことが明確な枝を除外し、不明な枝内で新しい型・値の警告を断定しません。
- **例外処理**：明白な組み込み例外とhandler型を照合し、捕捉できる問題を警告から情報noteへ変更します。handlerの再束縛・別名も確認し、不明なcontext managerやfinallyの制御移動では断定を控えます。
- **説明テンプレート**：RecursionError、StopIteration、AssertionError、RuntimeError、UnicodeDecodeError、UnboundLocalErrorを追加。RuntimeErrorは辞書・集合の走査中変更と一般メッセージを分けます。再帰深度の超過を常に無限再帰と決め付けません。
- **SyntaxError**：CPythonのメッセージとコードの形から、コロン不足、条件式の `=`、括弧・文字列の閉じ忘れ、余分な字下げへ確認を具体化します。比較 `==` を唯一の答えとは断定しません。
- **ヒント**：新しいAST所見を3段階のヒントへ接続し、最初は行・操作の確認、次に型や値の確認、最後に具体的な診断候補を示します。既存のNameError・類似名ヒントを維持しました。

未知の呼び出し、別名・コンテナ変更、暗黙的なユーザー定義処理を越えて、古い値・長さ・キー・関数定義を利用しません。この保守的な方針は、検出を控える代わりに誤警告を抑えます。高信頼度も「この行がこの値で実行されると問題になる」という静的事実であり、実行全体の唯一の原因や修正の正しさを保証しません。

## テストと一般化の確認

改善前の208アプリテストの6ファイルはバイト単位で未変更です。新規診断テスト105件と、新しいカテゴリによる既存パラメータテスト6件を追加し、アプリは319件になりました。評価器は元34件の旧Version前提4箇所を承認済み方針に沿って更新し、採点関数の同一性など8件を追加、計42件です。合計 **361件成功、27.49秒** です。

新規テストは警告の正例に加え、正常なdefault・可変長引数、両分岐での定義、catch済み例外、変更・別名・未知呼び出し、短絡評価、generator、propertyなどの暗黙的副作用、handler再束縛、finally、到達しない行を検証します。レビューの再現テストを追加してから修正しました。レビューではデータセット・holdoutを参照しない独立したコード検査も行っています。

アプリ・採点関数・テストのhashを固定後、20件の新規構造のholdoutを作成しました。結果を見た後のアプリ修正はしていません。全結果・時刻は [COMPARISON.md](COMPARISON.md) と [implementation_freeze.json](implementation_freeze.json) を参照してください。

## 残るStrict FAIL 14件の分類

自動評価の失敗分類は旧ルールのままresults.jsonに残しています。以下は実際の新しい出力も確認した人手の補足分類です。スコアを上書きしていません。

| ケース | 現状と原因 | 対応方針 |
|---|---|---|
| PY-009、010、011 | import先・ファイルの存在は実行環境次第。ログ説明・import対応はあるがコードだけでは警告しない | 静的解析だけでの断定を控えることが合理的。環境情報を任意で受け取る方式を検討 |
| PY-025〜030 | 再帰、空イテレータ、assert、辞書・set走査中変更、UTF-8復号の6件。説明テンプレートは達成したが、コードだけの問題findingは未対応 | ツール側の拡張余地あり。ただし再帰・イテレータは実行状態依存。明白な部分だけ個別に追加する |
| PY-034 | 自作クラスのname属性の存在・age属性の不足を推論しない。アクセス位置のみ示す | 型・属性解析の拡張余地あり。動的属性や継承のある一般ケースは断定困難 |
| PY-022 | `hello` の最大1位置引数に2個という `call_arguments` はある。固定規則が「定義より多い位置引数」の語順を拾わない | 評価器側の表現照合の限界。今回FAILのまま保存 |
| PY-031 | bytesとstrの不正な加算を診断済み。固定規則が「混在」等の別表現だけを拾う | 評価器側の表現照合の限界。今回FAILのまま保存 |
| PY-036 | builtinsを無警告にし、組み込み名としての参照noteもある。英語名と日本語が隣接する境界を照合できない | 評価器側の識別子境界の限界。今回FAILのまま保存 |
| PY-042 | ZeroDivisionErrorを捕捉できるnoteがあり、警告も0。英語名と日本語が隣接する境界を照合できない | 評価器側の識別子境界の限界。今回FAILのまま保存 |

上のうち、環境依存3件・未対応静的診断6件・自作クラス1件が、実際の機能範囲に関係する失敗です。4件は実際の所見を固定評価器が認識しない失敗です。holdoutの唯一のFAIL H-15も同じ例外捕捉noteの境界問題です。これらを補正した別の正解率は掲載していません。

## False Positiveと禁止断定

元42件の正常5件はBefore/Afterとも誤警告0件。holdoutの正常10件もBefore/Afterとも0件でした。合計15種類の正常コードで観測した結果であり、未知の正常コードすべてに誤警告がないことを意味しません。

元42件の禁止事項がある14ケース17項目、holdoutの5ケース5項目は自動照合で違反0件です。保存した説明・確認ポイント・ヒント・修正例の注記・AST所見・notesも読み、意図した変数名の保証、修正の保証、捕捉済み例外での停止、環境依存ファイルの存在否定、全経路での定義保証を断定する文章は確認しませんでした。

正常コードの空ログでは従来の「ログからエラー種類を読み取れない」という説明が返ります。これは警告findingとして数えていません。アプリが正常性を証明したり、新しいコード単独UIを提供するという評価ではありません。

## 次に改善価値が高い項目TOP5

1. **所見に構造化した根拠を付け、評価器を日本語の語順・英語名の境界に依存させない**。欠損属性の型、演算の両型、引数の必要数・指定数、捕捉例外を専用フィールドへ保持する。評価器を変更する際は現行の結果を残し、旧・新採点の両方を報告する。
2. **限定した安全な静的診断の追加**。明白な `assert False`、既知の空イテレータへのnext、直線的なコンテナ走査中のサイズ変更から始め、catch・短絡・早期終了による誤警告の回帰テストを先に追加する。
3. **分岐の定義状態と関数間の影響を構造化する**。未知の呼び出しで全情報を失う代わりに、変更され得る名前・値を限定する仕組みを検討する。引数や戻り値の伝播は小さい純粋関数から始める。
4. **単純なクラスの属性情報**。継承・decorator・動的属性のないクラスに限定し、`__init__` の全経路で代入される属性を候補として示す。既知でない属性を断定的な不存在へ変換しない。
5. **外部の正常コードを増やした評価と信頼度の校正**。授業・公開例から独立に用意したコードを使用し、誤警告、ヒントの有用性、候補の信頼度を測る。20件の自作holdoutだけで一般精度を主張しない。

## 現在の限界

完全なPython型推論・CFG・関数間解析ではありません。関数引数の実値・戻り値、データ依存の到達可能性、ユーザー定義クラス・descriptor・generatorの実行状態、環境内のモジュール・ファイルの存在は完全には理解できません。副作用や例外抑制が不明な構文では診断を控えるため、見逃しは残ります。入力コードの実行はアプリの機能に追加していません。
